# Configuration, autogen, aliases, hardware definitions

All four must be byte-compatible inputs for evok-node. This document is the parsing spec
plus the traps found by reading `evok/config.py` and `evok/modbus_slave.py`.

> **Clarified 2026-08-10 — which of the four the *daemon* reads.** "Byte-compatible input" no
> longer means all four are read at runtime, and the distinction is load-bearing:
>
> - **§1 `config.yaml` and §3 aliases** are inputs to the **one-shot migration tool only**
>   (ADR-0015). The daemon reads its own `/etc/evok-node/config.yaml` and its own store, and has
>   no knowledge of these formats. Do not build a runtime fallback to `/etc/evok` into the config
>   loader — that was an earlier design, and it was rejected.
> - **§2 `autogen.yaml` and §4 `hw_definitions/*.yaml`** remain **runtime daemon inputs**, read
>   from the OS image as EVOK reads them. Unchanged.
>
> Everything below stays authoritative as the parsing spec; only the consumer changed.

---

## 1. `/etc/evok/config.yaml`

Loaded from `/etc/evok` if that directory exists, otherwise from a directory next to the
package (which EVOK will `mkdir`). Only `config.yaml` is read by name; if
`autogen: true` is set, `/etc/evok/autogen.yaml` is **prepended** to the scope and the two
are deep-merged (later files win, dicts merged recursively). `[V-src]`

```yaml
autogen: true                    # include /etc/evok/autogen.yaml

logging:
  level: WARNING                 # CRITICAL|ERROR|WARNING|INFO|DEBUG
  file: /var/log/evok.log        # optional; TimedRotatingFileHandler, daily, 7 backups

apis:
  port: 8080                     # default 8080
  address: 127.0.0.1             # empty/absent ⇒ all interfaces
  websocket:
    enabled: true
    all_filtered: false
  webhook:
    enabled: false
    address: http://127.0.0.1:80         # code default: http://127.0.0.1:80/index.html
    device_mask: ["input","wd"]          # code default: ["di","sensor","watchdog"]
    complex_events: false

comm_channels:
  <bus_name>:
    type: MODBUSTCP | MODBUSRTU | OWFS
    enabled: true                        # optional, default true
    # MODBUSTCP:  hostname (def 127.0.0.1), port (def 502)
    # MODBUSRTU:  port (required), baudrate (def 19200), parity (def N), stopbits (def 1)
    # OWFS:       interval (def 60), scan_interval (def 300), owpower (circuit, optional)
    device_info:                         # optional, bus-level
      family: Neuron
      model: L533
      sn: 0
      board_count: 3
    devices:
      <device_name>:
        enabled: true                    # optional
        slave-id: 1                      # note the HYPHEN; default 1
        model: "00"                      # hw_definitions file name
        scan_frequency: 50               # Hz-ish; default 50
        scan_enabled: true               # default true
        device_info: {...}               # optional, per-device override
```

### Parsing traps `[V-src]`

- The key is **`slave-id`** with a hyphen, not `slave_id`. The docs use both spellings in
  different places; only the hyphenated one is read.
- `model` values are YAML-sensitive: internal board codes are two hex digits (`00`, `13`)
  and **must be quoted** or YAML turns `00` into the integer 0. Our loader should coerce to
  string and accept both.
- Bus type `OWFS` is what the code matches; the docs say `OWBUS`. Accept both.
- Device-level 1-Wire sensors (`type`, `address` under an OWFS bus's `devices:`) call
  `device_data.getintdef(...)` on a plain dict → `AttributeError`. **Static 1-Wire sensors
  are broken upstream**; implement them properly.
- `scan_frequency: 0` is silently converted to a `0.0001 s` interval — a **10 kHz poll
  loop**. Reject it, or make it mean `mode: onDemand` explicitly.
- Sections missing from the config produce only a warning, never an error.
- `device_info.family` is auto-set to `Extension` when `model` starts with
  `xs/xm/xl/xg` (case-insensitive) and family is `unknown`.
- Nothing validates: duplicate `slave-id` on one bus, duplicate device names across buses,
  duplicate circuit names, or two circuits mapping to the same coil. Open issue **#131**.
  All four should be hard startup errors in evok-node.

### `scan_frequency` semantics

`scan_interval = 1 / scan_frequency` seconds, per **device** (not per block). Each register
block additionally carries a `frequency` *divisor*: the block is read every
`scan_interval × frequency` seconds. So `scan_frequency: 50` + `frequency: 10` ⇒ that block
is read every 0.2 s. `[V-src]`

The implementation of the divisor is a per-block counter compared with `>=`, reset to `1`
(not 0) after a read, and initialised to `10000001` so every block reads on the first pass.
`[V-src]`

## 2. `/etc/evok/autogen.yaml`

Generated by `unipi-os-configurator` (binary `/opt/unipi/tools/os-configurator`, force with
`-f`) from `unipiid` data, regenerated when hardware change is detected. Rules: `[V]`

- The bus is **always** named `LOCAL_TCP`.
- Device names are the `slave-id`, which on standard controllers equals the section number.
- A bus-level `device_info` block describes the unit (`family`, `model`, `sn`, `board_count`).
- An `OWFS` section is emitted only if the device supports 1-Wire **and** the `owserver`
  package is installed; `owpower` only if the controller supports it.

```yaml
comm_channels:
  LOCAL_TCP:
    type: MODBUSTCP
    hostname: 127.0.0.1
    port: 502
    device_info: {family: Neuron, model: L533, sn: 0, board_count: 3}
    devices:
      1: {slave-id: 1, model: "00"}
      2: {slave-id: 2, model: "13"}
      3: {slave-id: 3, model: "13"}
  OWFS:
    type: OWBUS          # docs show OWBUS; code matches OWFS — accept both
    interval: 10
    scan_interval: 60
    owpower: 1
```

**evok-node decision:** consume `autogen.yaml` when present (that is the compatibility
requirement), but also implement our own equivalent generator so we don't hard-depend on
`unipi-os-configurator`. Sources for it: `unipiid` files under `/run/unipi-plc/unipi-id/`,
the per-section sysfs board name/serial/firmware, and — as a cross-check — holding
registers 1001/1002/1004 on each unit-id. Use `unipiid fingerprint` as the cache key.

## 3. Aliases

**File**: `/var/lib/evok/alias.yaml` (singular — the docs' `aliases.yaml` is wrong). `[V-src]`

Two versions, with automatic in-memory upgrade:

```yaml
# version 1.0 (EVOK v2) — a LIST, key `dev_type`, devtype as a NUMBER
version: 1.0
aliases:
  - name: my_relay
    circuit: '1_01'
    dev_type: 0

# version 2.0 (EVOK v3) — a MAP, key `devtype`
version: 2.0
aliases:
  my_relay:  {circuit: '1_01', devtype: ro}
  my_input:  {circuit: '1_01', devtype: di}
```

Loader behaviour: `[V-src]`

- `version: 1.0` → transformed to the v2.0 map shape, `dev_type` → `devtype`.
- `version: 2.0` → used as-is.
- **Any other or missing `version` → the alias file is silently ignored** (result `{}`).
  Note the docs' own example in `aliases.md` writes `version: 2.0` unquoted, which YAML
  parses as the float `2.0`; the code compares against both the string and the raw value in
  different places. Be liberal on read.
- A numeric `devtype` anywhere is mapped through `num_to_devtype_name` with a
  `"Detected old devtype! Upgrading..."` warning.
- An alias pointing at a circuit that doesn't exist on the current hardware raises during
  device registration and is caught per-entry with a warning — **the alias is dropped**,
  not retained. If the hardware appears later, the alias does not re-bind.

Persistence: `[V-src]`

- Aliases live in RAM and are flushed by a background task **300 s (5 min)** after the
  first change (`AliasTask.SAVE_TIME = 300`), or immediately on a forced save.
- Force save: `POST /rest/run/alias` with `save=1`.
- The write is `open(path, 'w+')` → `write(yaml.dump(...))` → `os.system('sync')`:
  **truncate-then-write, no temp file, no rename**. A power cut mid-write leaves a
  truncated or empty alias file. Use temp-file + fsync + atomic rename.
- No flush on shutdown: `shutdown()` calls `alias_task.cancel()` and stops the loop —
  **up to 5 minutes of alias changes are lost on a clean restart**.

Validation: names must be alphanumerics, `-`, `_`, `.`, and globally unique across types.
The implemented check is `len(re.findall(r"[A-Za-z0-9\-\._]*", alias)) > 2`, which — because
`*` matches empty strings — does not do what it looks like. Write a real
`/^[A-Za-z0-9._-]+$/` test plus a reserved-word list (`all`, `alias`, and every device
type name, since those occupy the same URL slot).

## 4. `/etc/evok/hw_definitions/*.yaml`

One file per Modbus device model; **the file name (minus `.yaml`) is the `model` key**.
Loaded eagerly at startup; empty files are warned about and skipped; a missing directory is
an error log, not a failure. `[V-src]`

```yaml
modbus_register_blocks:          # what to poll
  - start_reg: 0
    count: 10
    frequency: 1                 # read every scan_interval × frequency seconds
    type: holding                # holding (default) | input

modbus_features:                 # how to slice registers into API devices
  - type: DI | DO | RO | AI | AO | BAO | LED | WD | REGISTER | DATA_POINT | OWPOWER | NV_SAVE
    count: 4
    reg_type: holding | input    # DATA_POINT / REGISTER only
    ...type-specific fields...
```

### Feature types and their fields `[V-src]`

| type | fields | produces |
|---|---|---|
| `DI` | `val_reg`, `counter_reg`, `deboun_reg`, `modes[]`, plus optional `ds_modes[]` + `direct_reg` + `polar_reg` + `toggle_reg` (all four required together for DirectSwitch), optional `start_index` | `di` |
| `RO` | `val_reg`, `val_coil` | `ro` |
| `DO` | `val_reg`, `val_coil`, `modes[]`, and **either** hard PWM (`pwm_reg`+`pwm_ps_reg`+`pwm_c_reg`) **or** soft PWM (`pwm_reg`+`pwm_preset_reg`+`pwm_cpres_reg`) — otherwise `ValueError` | `do` |
| `AI` | `val_reg` (stride **2** per channel), `mode_reg` (stride 1, optional), `modes{}` | `ai` |
| `AO` | `val_reg`, `mode_reg` (optional), `modes{}` | `ao` |
| `BAO` | `val_reg`, `mode_reg`, `res_val_reg` — the section-1 "Brain" AO with resistance measurement | `ao` |
| `LED` | `val_reg`, `val_coil` | `led` |
| `WD` | `val_reg`, `timeout_reg`, `nv_sav_coil`, `reset_coil` | `wd` |
| `REGISTER` | `start_reg`, `reg_type` | `register` (circuit gets `_inp` suffix for input regs) |
| `DATA_POINT` | `value_reg`, `name`, `unit`, `datatype` (`null`\|`float32`), `offset`, `factor`, `valid_mask_reg`, `reg_type`, `post_write` | `data_point` |
| `OWPOWER` | `val_coil` | `owpower` |
| `NV_SAVE` | `val_coil` | `nv_save` |

Note `nv_sav_coil` — the WD field name is **not** `nv_save_coil`, despite the constructor
parameter being spelled that way. Open issue **#207** is about exactly this. `LED` is
undocumented upstream (issue **#206**).

### Address arithmetic, and the bug in it

Per-channel addressing as implemented: `[V-src]`

```python
DI:  circuit = f"{name}_{i+1+start_index:02d}"
     mask = 1 << (i % 16)
     regdebounce = deboun_reg + i
     regcounter  = counter_reg + 2*i          # 32-bit, two registers
     val_reg is NOT advanced per bank
RO:  circuit = f"{name}_{i+1:02d}";  coil = val_coil + i;  mask = 1 << (i % 16)
DO:  same as RO, plus pwmdutyreg = pwm_reg + i
LED: same as RO
AI:  val_reg + 2*i ;  mode_reg + i
AO:  val_reg + i
```

The mask correctly wraps with `% 16`, but **`val_reg` is never advanced by the bank stride
`floor(i/16)`**, and `RO`/`DO`/`LED` ignore `start_index`. On boards with more than 16
channels of one type (Neuron M403 has 28 ROs) the second bank's circuits either collide
with the first bank's names or read the wrong register while writing the right coil. The
field report on issue **#209**/**#195**: circuits `_01…_12` silently drove coils 116–127,
i.e. **relays 17–28**. `[V]`

This is the worst defect in the corpus — a named output actuating a different physical
relay — and it is open. See `04-known-bugs-and-lessons.md` §3.4 for the design rule.

### Definition-load validation evok-node should add

None of this exists upstream; all of it prevents a class of silent misbehaviour:

1. Strict schema per feature type; **fail the definition, not the process**, naming the
   file and field.
2. Every multi-register value (32-bit counter, `float32` AI) must lie **wholly within one
   register block with one `frequency`** — otherwise the two halves come from different
   points in time. Reject definitions that violate it.
3. Every computed address must fall inside some declared block, for the right register type.
4. Global uniqueness: no two devices share a circuit id; no two circuits map to the same
   coil or the same (register, bitmask).
5. Cross-check against the board: holding 1001/1002 give the DI/DO/AI/AO census; assert it
   matches the definition's counts and refuse to run on mismatch.
6. Definitions are loaded into **frozen** structures. Upstream's `copy()`→`deepcopy()` fix
   (`80c95f1`) exists because a shallow copy let every slave on a bus share one register
   cache — the kind of thing `readonly` types prevent at compile time.
7. Resolve models by explicit key lookup. Upstream had a bug where the loaded definition
   depended on **dict iteration order** (`a4ea47a`).

### Runtime behaviour to preserve

- `frequency` divisor semantics as described in §1.
- Register blocks are read in **one Modbus request each** — block layout is a performance
  contract, not just a filter.
- The register cache is per-**slave** (`ModbusSlave.modbus_cache_map`), created by the
  first `Board` and shared. Reads go through `get_register(count, index, is_input)`, which
  raises `ENoCacheRegister` if the value has never been read — so devices can exist with no
  value yet. Preserve the distinction between "no value yet" and "value 0"; our API should
  express it as `valid: false` / `stale: true` rather than a silent zero.
