# 2026-11-23 — M3.6 — Roles, scopes, hierarchy, WS extensions

Role: system designer and architect (after a sparring session, 2026-11-11 to 11-23). Task: M3.6, with 12a §6 and the 15 memo.

## Decisions with Tomas

- RBAC only, no ABAC. Reason: a rule on a device value (an `installer` reading) lets whoever can SET it escalate; a `device:` grant says the same.
- Fixed roles (`tenant:flat3`), no parameters. A role is an IdP group; its grants are an attribute of that group; shared grants through group parents (`resident`). Reason: assignment is plain group membership in authentik.
- All grants in the IdP, `device:` ones too — no node-local assignments. `until` on assignments dropped.
- Scopes `site`, `node:`, `zone:` (covers the subtree), `device:<node>/<address>`. `nodeId` in `driver-auth`'s config.
- ACL checked per request against one hierarchy copy, not a per-session table. Reason: no reaction needed to device changes; cheap.
- `proof` binding, enforced by the api.
- Hierarchy reworked: zone tree (`parentId`) → room → group; level is an object that only labels a room. Zone ids site-wide, chosen by the admin; parents per node, admin's responsibility; warning when an attached node's remote zone differs.
- WS extensions: module-like descriptor (config, rules, declaredLinks, create once), hooks in onion order (before/after for request and introspection, onPush), the api offers services and stays agnostic; an extension sees only what clients see, plus its own private drivers (e.g. `driver-auth`). Home API fixes auth and ACL; WS API lists them in config.
- New design step M3.7b for plugins in general (02b); nested plugin config moves there.

- Level gets `story` (integer, order; same number = same story).

- Management is per home driver; a flat with its own manager gets its own home driver (one PLC per top zone in practice), importing between them. Reason: no argument-scoped checks needed.
- Grants attribute `{ evok: { v, grants } }` on any group; inheritance computed by the replica; per-grant checks at sync, a bad grant skipped and reported, sync never fails as a whole.

- WS API checks access marks exactly as the Home API: as written, no override, no client profiles.

- PLC to PLC (D16, D9): node = principal with grants; Ed25519 node key; mutual challenge-response, no clock; peers only from the IdP when a site IdP is configured, local pairing only when `driver-auth` is the master; delegation for calls relayed for a user. Reason: links must work with the IdP down; one source of truth per mode.

- D1 one driver. D2 key-bound ID token, one evok app in the IdP. D3 the shell holds the IdP session; a node is BFF only for a plain browser. D7 as the research lean. D11 biometry-only B, PIN fallback. D13 phone keys per node.
- D12 one canonical name per node + split-horizon DNS; node keeps its own certificate (DNS-01) so the LAN does not depend on the reverse proxy; `.local` for discovery and redirect only; the shell routes over the LAN by mDNS, identity checked by the node key. Reason: one origin = one cookie, one passkey, one redirect URI.

- D4 levels `l1`/`l2` + per-call proof. A "trusted anonymous" level on the home network was considered and dropped: the network position would be the credential (TVs, IoT, guests on the main wifi). Kiosks are enrolled `client:` principals; guests are IdP users with a PIN.
- D5 `ack` only within 5 min of a fresh `uv`.
- D6 the PIN identifies the user; 6+ digits; set by admins in the IdP, which drives 2N Access Commander; clear PIN readable only by its LDAP account, nodes sync only an Argon2id hash. Uniqueness-check leak and generated PINs deferred.

- D10, D14, D17–D21 as the research leans: rules with `l2` consent at creation; offline logins on the saved time, logged; not-relayable mark; own SQLite; `AccessClosure`; own token service on `jose` + `openid-client`; sync 5 min + webhook hint.
