## Design step — `TimerRelay` (role: system designer, 2026-10-25)

- Virtual device, template `timer`, no roles: rules start it and react to its readings; never drives a load (Tomas).
- `state` idle/elapsing/paused; running = elapsing or paused. Retrigger is not a setting: one method per reaction — `start` (ignore), `restart`, `add`, `toggle`; plus `pause`, `resume`, `cancel` (Tomas).
- Running + `toggle`/`start`: `ms` ignored. Over `maxMs`: clamped. `toggle`/`cancel` never emit `elapsed`.
- `warning` is a bool reading. Resolution ms. No repeat/flasher setting.
- `persistent`: `endsAt` in wall-clock time; a passed expiry fires `elapsed` at start, after the rule engine's baselines. Named exception: 04 §4.1a `WallClock`. Debounced save loss accepted.
- Not on Matter. Renamed `Timer` → `TimerRelay` everywhere.
- Rules: only `on-and-set-delay-off` (option `method`, default `restart`; with `toggle` on a running timer it switches lights off) and `delay-off` (on `elapsed`).
