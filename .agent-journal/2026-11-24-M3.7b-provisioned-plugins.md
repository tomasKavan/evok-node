# 2026-11-24 — M3.7b — Provisioned deployments

Role: system designer and architect. Addition to M3.7b: deployments by automation (Ansible) with a fixed set of npm plugin packages, static config only, no package changes from the Inspector.

## Decisions with Tomas

- `main.plugins.locked` is its own switch, independent of `dynamicConfig`. Reason: a static config may still leave packages to the Inspector (home templates and rules live in KV).
- The declared set lives in the static config, `main.plugins.packages` (name → npm spec).

## Choices made while writing

- `packages` needs `locked: true` (`packages-need-lock`, fatal as a static-file issue) — otherwise the Inspector and sync would both own the user root.
- `evok-node plugins sync [--update]`: stages exactly `packages` as `next`, same generations and checks as the Inspector; prints `unchanged`/`staged` for Ansible's `changed_when`; never run by the daemon, so a boot needs no network.
- `file:` tarball specs for offline fleets; unchanged also compares their sha512.
- Drift at startup is `plugins-drift`, not fatal.
- Static mode no longer blocks package writes by itself; only `locked` does.
- Removed 02b §12's upload-size Open — the WS API §9 covers it.
