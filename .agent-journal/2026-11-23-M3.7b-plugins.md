# 2026-11-23 — M3.7b — Plugins: general rules

Role: system designer and architect. Task: M3.7b — redesign plugins as one mechanism, 02b, and align every plugin kind's doc.

## Decisions with Tomas

- Redesign from scratch rather than patch 02 §4: package → plugins → kind → owner. Reason: each kind had its own id field, registration path and failure rule.
- Drop direct registration (`registerKind`, `registerHandshake`, `registerCtrl`); the manifest is the only registry. Cost accepted: a lazy `import()` for built-ins too.
- Vendor prefix required on plugin ids; built-ins unprefixed, and the namespaces they use reserved.
- A problem in a plugin package disables that package; in a built-in it is a bug, fatal.
- Install from the npm registry and from an uploaded `.tgz`, both through `npm install --omit=dev --ignore-scripts`; native code prebuilt.
- `modbus-kind-binder` renamed `modbus-binder`.
- A package may define its own kind (`defines`), inside its namespace; `requires` names the owner.
- `PluginMeta` once per plugin (`metaOf`), once per kind — not repeated in `describe`.

## Choices made while writing

- `module-sdk` owns `driver`, `api` and `device`; `main` owns no kind.
- `Configurable` (meta, config, rules, declaredLinks) shared by `ModuleDescriptor`, `WsExtensionDescriptor`, `DaliControllerFactory`; `nestable` kinds go in config through `Values.plugin` → `{ use, config }`; `main` walks the body for them.
- DALI: `daliCtrlKind` + `ctrl` merged into `ctrl: { use, config }`. WS API: `extensions:` a list, order = onion order.
- `ModbusHandshake { name, meta?, run }` replaces a bare function; `DeviceType` and `ModbusKindBinder` get optional `meta`.
- Templates, bundles, rule kinds: `label`/`hint` → `meta`, also in `listTemplates`/`listBundleKinds`/`listRuleKinds`.
- Hardware definitions as a `data` kind `hw-definition`; files under `/etc/evok-node/hw_definitions/` resolve first. 10: two definitions claiming one family code fail `configure()`.
- User packages in npm generations `current`/`next`/`previous`; `current` never touched while running (lazy loads); `plugins.json` for disabled packages; `main.plugins.registry`.
- `main` driver package methods, `administer` + proof; `in-use` only for static entries — a dynamic user is reported in `usedBy`, left out after restart.
- A template that no longer resolves leaves the device `missing` (12a §4.2).
