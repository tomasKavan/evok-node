# 2026-11-24 — M3.7b — The `evok-node` command and the daemon's user

Role: system designer and architect. Closes the Open left by provisioned deployments: what `evok-node` is, who runs `plugins sync`.

## Decisions with Tomas

- The daemon does not run as root by default; running as root stays possible.
- `config check` is in scope.

## Choices made while writing

- One executable `/usr/bin/evok-node` (`bin` of `@evok-node/main`): `run`, `config check [file]`, `plugins sync [--config file] [--update]`; `--json` for automation.
- Every subcommand runs as the owner of `/var/lib/evok-node/`; from root it switches, from another user it exits 1. Reason: the user root must never hold a file the daemon can't write.
- System user `evok-node`, group `dialout`, `CAP_NET_BIND_SERVICE`, `Restart=always`; `/etc/evok-node` root:evok-node 0750/0640.
- Root through a systemd drop-in plus `chown` of `/var/lib/evok-node`; the daemon warns when it runs as root.
- `config check` uses `next` when staged; `plugins sync --config` reads a candidate file. So the Ansible play syncs from a candidate config first, then writes the real one with `validate: evok-node config check %s`.
- `ExecReload` sends SIGHUP — assumed; 02 §5.1 only says `systemctl reload`.
- `.lock` file shared by `plugins sync` and the `main` driver's staging.
