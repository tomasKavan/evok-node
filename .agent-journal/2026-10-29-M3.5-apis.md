# M3.5 — APIs: common contract (system designer)

## Decisions with Tomas
- Naming: API module / API plugin (third-party API module) / WS extension (`onConnection`, `onRequest`); relay vs mapping api.
- `ws-kit` generalizes the WS server; WS API and Home API built on it; Matter bridge stands alone.
- No "declare heavy": child_process is a recommendation for native code / long CPU.
- No api-kit: consumer tools already in module-sdk; only `links()`/`onLink` added to MessagingHandle (03 §4), which also gives an api its `drivers:`.
- Auth and ACL only at the api (the gate). No shared user model across apis. A driver needing the user takes it as a method argument annotated `actor`; api always overwrites it. `proof` marks a method. Reverses old 12c-09 §1.2 ("never a method argument").
- `Origin.client` kept, for logs/debugging only.
- Errors: relay apis send ResponseError as is; mapping apis map; internal-error only as a reference.
- Listening: defaults per api, no declaration to main; EADDRINUSE reports itself.
